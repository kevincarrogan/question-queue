Decisions so far

Full reasoning in docs/design.md

Named so the initials spell the command

Question Queue, qq. On PyPI as question-queue (MIT), because quarry and qq are taken.

An outliner, not questions and answers

Every list item is an item. A question is just one ending in ?, and its answer is an item under it. Files from the first version still open.

Each item is a subject and a body

The first line is what the outline shows; the indented lines under it are the rest, like a commit message.

Two panes keep moving and typing apart

Outline keys are commands and never type; the editor is where you type, and → takes you there. Replaced the one-mode ctrl-key design.

Capture first, place later

enter adds where you are, n adds at the bottom and puts you back, and m or shift+arrows move it afterwards.

Your file comes back untouched

Items you haven't changed are written back exactly as read. IDs are added as soon as a file opens, so other tools see the same ones.

Ticks follow the boxes under them

Partly done shows [-] but stays [ ] in the file, so it's still plain markdown. A plain item stops the cascade.

The palette depends on the pane

/ means this item in the editor, // means everywhere. A replace is literal and needs the closing slash.

Undo is a stack of file snapshots

Every change, IDs included, up to 200 deep; a run of moves of one item is one step. Reloading after an outside edit clears it.

Never overwrite someone else's edit

If the file changes on disk, qq reloads. With unsaved edits, it asks whether to reload or keep yours.

Core has no UI code

Everything works by item ID, so the MCP server and VS Code extension can reuse it. next_open, finish the branch then widen, waits there for them.

Plain qq finds the nearest .qq folder

Like git finds .git. With none, it asks: start one here, or use the global ~/.qq.
