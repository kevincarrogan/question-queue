Decisions so far

Full reasoning in docs/design.md

Named so the initials spell the command

Question Queue, qq. Published as question-queue, because quarry and qq are taken on PyPI.

Your notes come back untouched

Questions you haven't changed are written back exactly as read. Unrecognised lines keep their place.

Esc leaves the answer editor

Otherwise n, r and u would be typed into answers. Ctrl keys work in both modes.

IDs are saved as soon as a file opens

So another tool reading the file sees the same IDs that qq uses.

Next open returns to the parent

Finish the branch, then widen one level at a time. See the board on the left.

Never overwrite someone else's edit

If the file changes on disk, qq reloads. With unsaved edits, it asks whether to reload or keep yours.

Delete takes the whole subtree

It asks first when the question has children.

Core has no UI code

Everything works by question ID, so the MCP server and VS Code extension can reuse it as is.
