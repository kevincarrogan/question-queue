Ideas and next steps

Next

MCP server

Let an LLM drive the tree through tool calls. Wrap DocumentFile and core.ops directly.

  • One operation per call: load, apply, save
  • On ExternalChange, reload and retry rather than force
  • next_open and trail as the "what next" and "where am I" tools
  • An open qq already reloads on its writes
Then

VS Code extension

The same focus and outline views beside the code, on the same file.

  • Talks to the core over the MCP server, or a small local API
  • Has to keep the file format exactly as qq writes it
Later

Remote and phone

  • Needs sync, which v1 left out on purpose
  • Parking is the phone's main job
