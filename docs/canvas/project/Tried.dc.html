01 · First build

Two views and a mode switch

Where should we go in June?
Which stretch of coast?
The north coast.
esc for commands
n N r park · u up · q quittab: outline
  • A focus view for one question, and an outline view on tab for arranging
  • Single-letter keys, so esc left the answer to make them commands

Why we moved on: too much to learn before asking a single question.

02 · Cut down

Three keys, one mode

  • Always typing into the answer; ctrl+n ask, ctrl+d done and next, ctrl+q quit
  • A guide on the empty screen

Why we moved on: easy to learn, but one question at a time hid the shape of the file.

03 · Like the file

Reads like the markdown

  • The whole file drawn as markdown, IDs hidden, answers typed in place
  • Then to-dos ([ ]) and file references on top

Why we moved on: it was still questions and answers, and most of what goes in isn't either.

04 · Now

An outliner in two panes

  • Items, not questions and answers; a first line and a body, like a commit
  • enter adds here, n at the bottom, m picks one up to carry it

Why it holds: moving and typing never share a key, and the pane with focus says which you're doing.

Since the two panes
Arrow keys ← folds or goes to the parent. → unfolds, or edits: the editor is the pane to the right.
The palette ctrl+p, vim-style: /find, //everywhere, :34, /old/new/gi.
Cascading ticks A parent is ticked once all its boxes are, and shows [-] while only some are.
Clickable references Click a file:line in the outline and it opens in VS Code.
